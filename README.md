# Career Quest

MVP для HackAlem AI / Halyk Bank: развитие сотрудников на Python и Streamlit.

## Запуск

Python 3.9+; выполнять из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Если окружение уже создано: `.venv/bin/python -m streamlit run app.py`.
Откройте http://localhost:8501. Папка `career_quest_dataset` должна лежать рядом с `app.py`.

## Демо

1. В Employee выберите сотрудника: профиль, навыки, readiness и до трёх рекомендаций.
2. Откройте breakdown: баллы рассчитаны детерминированно, без LLM/API.
3. Нажмите **Complete activity**: навыки, readiness, рекомендации и HR Dashboard пересчитаются.
4. В **Judge Upload Mode** загрузите employee JSON и при необходимости историю CSV.

Загрузка принимает исходный объект `{ "meta": ..., "employees": [...] }`, массив сотрудников
или один объект employee с реальными полями датасета. Обязательны `employee_id`, `role`,
`grade`, `skills`; отсутствующий skill считается равным 0. CSV использует исходные названия
столбцов, UTF-8 и запятую; обязательны `record_id`, `employee_id`, `event_id`, `date`, `status`.
Загруженная история должна относиться к сотрудникам загруженного JSON и иметь уникальные
record_id. При совпадении employee_id заменяются только его профиль, история и демо-прогресс
в текущей сессии. Без CSV история загруженного профиля считается пустой. Неверный upload
покажет сообщение и не изменит текущее состояние.

Данные читаются на дату среза `2026-10-01`. Завершения после `last_review_date` применяются
однократно. Если дата оценки отсутствует, используются переданные уровни без повторного
начисления истории; приложение показывает предупреждение.
Complete activity — симуляция завершения на дату среза. Изменения хранятся в session_state;
перезагрузка страницы или новая сессия возвращает исходные данные. Файлы датасета не изменяются.

## Расчёт

- Следующий grade текущей роли: Junior → Middle → Senior → Lead. Для Lead следующего grade нет.
- Readiness: `100 × Σ min(current, required) / Σ required`. Критические gaps показаны отдельно.
- Активности фильтруются по роли, текущему grade, prerequisites, расписанию, истории и полезному gain.
  Обязательные мероприятия исключены. Завершённые не повторяются, кроме EV_036 (правило README датасета).
- Повышение: `max(0, min(gain, max_level − current))`; навык никогда не снижается.
- Score: до 30 за относительные gaps, 25 за долю критического gain, 35 за долю закрываемого
  суммарного gap, 10 за похожие завершения, штраф до 30 за no_show/declined/dropped.
  Похожесть — доля общих навыков в объединении навыков двух активностей. Формулы и вклады
  раскрыты в интерфейсе и `recommender.py`; score — балл приоритета, а не вероятность успеха.
- Career goal показана справочно. Повышение grade автоматически не производится.

## Файлы и проверки

`app.py` — интерфейс и session_state; `data_loader.py` — чтение и валидация;
`recommender.py` — общая логика для всех профилей; `hr_dashboard.py` — HR статистика.

```bash
python -m unittest discover -s tests -v
python -m pip check
```

Тесты проверяют реальный каталог, влияние истории, ограничения gain, upload и сценарий завершения.
