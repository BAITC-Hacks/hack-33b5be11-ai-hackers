## Ответы на ожидаемые вопросы

- **Это LLM?** Основные шаги вычисляет объяснимый движок. Опциональный AI-агент использует LLM и четыре read-only инструмента, выбирая из допустимых вариантов. На защите подтверждаем живой режим по `mode=openai` и выполненным tools. Если сработал fallback, прямо называем это резервным режимом.
- **Почему не минимальный навык?** Важен дефицит относительно цели, критичность, допуск, история и трудозатраты. Минимальный навык может не влиять на целевой грейд.
- **Покрытие 100% означает повышение?** Нет. Это соответствие формальным требованиям навыков; решение требует подтверждения компетенций и участия руководителя.
- **Что с приватностью?** Локальное демо на синтетике; после входа сервер ограничивает доступы. Выбор демо-профиля не заменяет корпоративный SSO.
- **Как подтверждён эффект?** Автотесты проверяют расчёты и ограничения. Продуктовый эффект и превосходство рекомендаций пока не доказаны: для этого нужен пилот и экспертная оценка.

Перед защитой: проверить браузер и импорт; сделать копию `var/state.json` для восстановления чистого демо; запустить на втором ноутбуке; не добавлять новые функции в последний час.


## Перед сдачей

1. Использовать только web: `.venv/bin/python run.py --ask-key` (Streamlit — экспериментальный прототип).
2. Выполнить `.venv/bin/python scripts/check_live_ai.py`: нужен PASS, не fallback.
3. Прогнать `.venv/bin/python -B -m unittest discover -s tests -v`.
4. Проверить build ID внизу страницы после обновления кода.
5. Показать AI-кнопку; при превышении 8 секунд система возвращает объяснимую резервную рекомендацию.
